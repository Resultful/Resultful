## Done when

1. **A version per project.** Each packable project under `src/` declares its own version (keep `VersionPrefix`
   `0.2.0` + `VersionSuffix` `beta06` for `Resultful` until 04b, or `<Version>` — whichever keeps 01's
   `ResultfulPackageVersion` reader and the packed CI run working; adapt the reader if needed and say so).
2. **Change detection by path and project graph** (`eng/release-plan.cs`): a package's inputs are its project
   folder, its referenced projects' folders (transitively), `Directory.Build.props` files that apply, the root
   `README.md` and `LICENSE`, and the `Directory.Packages.props` entries it (transitively) uses. States `publish`,
   `pending`, `unchanged` as in the sibling. Tags are `<PackageId>/v<version>`. Bootstrapping: the existing
   `0.2.0-beta06` tag (or whatever tag the repo has for beta06; check `git tag`) counts as `Resultful`'s last
   release, and the decision text says how the old tag maps.
3. **`eng/release-plan.cs` tested against made-up change lists**: a test project (xunit.v3, under `tests/`) or a
   `--self-test` mode that builds fake repos/graphs and asserts the states, including a shared-project change
   showing dependants as pending, a version below the last release failing, and a test-only change leaving
   everything unchanged.
4. **The package check runs on every packable project** (`eng/verify-package.cs` iterates them), stricter for the
   packages in the plan, as in the sibling.
5. **CI**: the build job computes the plan and writes it to the step summary. The publish job (manual, `main` only,
   `publish` ticked) pushes only the planned packages and tags them after the push. **Nothing publishes in this
   PR**; never dispatch it. The stable publish path stays `main`-only.
6. A decision record for the Resultful side if decision 11 doesn't already cover the mechanics (status `proposed`),
   or an update to decision 11's consequences. Docs move with code (GOAL.md rule 7).
7. Every CI job passes; the counts, suppressions and release-check gates pass.
