## Done when

1. **The Shop** against the target API (compiled against the TargetApi stub assemblies for now; the real packages
   later), one folder per use case UC01–UC10, as VERIFY.md section 3 lays out:
   - `samples/Resultful.Shop.Domain`: closed hierarchies and shapes, a separate assembly on purpose.
   - `samples/Resultful.Shop.Api`: orders (UC1), sign-up (UC2, UC3), context (UC4), payments adapter (UC5).
   - `samples/Resultful.Shop.Worker`: a queue handler over an in-memory channel (UC6).
   - `samples/Resultful.Shop.Legacy`: UC10's "before" code, and a library with an `internal` `[MustObserve]` (UC9).
   - A `net11.0`-only folder whose errors are unions (decision 17), built only on net11.
   - A use case folder builds only when its ledger line (`UC0n` in `tests/Resultful.Spec/ledger.tsv`) is `done`
     (MSBuild condition reading the ledger, or an equivalent switch); all are `pending` now, so nothing in the Shop
     is compiled by default, but each folder compiles against the target stubs when forced (prove it locally).
   - Handlers use explicitly typed lambdas for generated `Match`/`Switch`/`TryMap` (RF0008).
2. **`tests/Resultful.EndToEnd`**, no `ProjectReference` to `src/`:
   - Packed-package restore: pack every packable project with a per-run version, restore into an isolated folder
     with package source mapping that sends `Resultful*` to the local feed only (Known traps, "Stale packages").
   - Build with `TreatWarningsAsErrors`, `AnalysisLevel latest-all`, nullable on.
   - `http-cases.json`: one request per error leaf with the status and ProblemDetails body, using the HTTP map in
     `DECISIONS-TAKEN.md` (400 ValidationProblemDetails, 404, 409, 500 with a fixed title and no `Message` outside
     Development). An OpenAPI check lists the success and each failure status.
   - Broken consumers under `Broken/*`, each must not build, each writes `<ErrorLog>` SARIF, and the runner compares
     the SARIF IDs with the expected IDs both ways: a missing arm, a discarded result, a `default` result, a type
     derived outside its base's assembly, a bare string into `Result<string>`, an untyped `Match` handler (RF0008),
     a reordered `Match` whose typed handlers no longer compile (CS0411).
   - Everything here is gated on the ledger like the Shop: the runner reports each case as `pending` today, and a
     pending case that passes fails ("flip this line"), the same rule as the spec harness.
3. **`eng`-style snippet check** (file-based app in the new directory, moved to `eng/check-snippets.cs` at
   wiring): tagged code blocks in the README and `docs/errors-in-practice.md` must equal tagged regions of the Shop.
   Lenient now (report differences, exit 0, with a `--strict` flag that 25 turns on). Self-test showing `--strict`
   fails on a seeded difference.
4. The `UC*` and `HTTP-*` ledger lines 04c listed get fixtures that point at the Shop and the cases file; their
   hashes in the ledger are updated as a `spec:` commit (one, listed in the PR body), states stay `pending`.
