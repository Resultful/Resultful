# Contract 02: test-infra (stack A, 0.2)

Branch: `rtkelly13/stack-02-test-infra`, based on `rtkelly13/stack-01-consumption-tests` (PR #38). Draft PR, base
`rtkelly13/stack-01-consumption-tests`.
Worktree: `temp/wt/02` (`git worktree add temp/wt/02 -b rtkelly13/stack-02-test-infra origin/rtkelly13/stack-01-consumption-tests`).

Implements: roadmap M1 testing, decision 6 (`docs/decisions/0006-tests-are-a-mix.md`). Stack A holds nothing about
0.3: no reference to unions, shapes, `Unit`-as-class, `Error` records, or anything from PR #34.
Read first: `stack-plan/GOAL.md` (rules), `stack-plan/VERIFY.md` sections 1 and 5, decisions 0005, 0006, 0007.

Done when:
- `eng/run-tests.cs` (file-based app, like `eng/verify-package.cs`) finds every `tests/*/*.csproj` and runs it for
  each target framework it declares, skipping `net481` (and any `.NETFramework` target) off Windows. CI calls it
  instead of listing test projects by hand. It writes a per-project, per-TFM count of passed/failed/skipped tests.
- **Counts gate.** `eng/test-counts.json` is committed with today's counts. CI fails if a project's total falls or
  its skips rise versus the file. Raising counts means updating the file in the same PR. A self-test shows the gate
  fails (e.g. a unit test of the comparison, or a CI step run against a doctored file).
- **Suppressions gate.** A script (`eng/check-suppressions.cs`) lists new `NoWarn`, `#pragma warning disable`,
  `Skip =`, `SuppressMessage` and `continue-on-error` lines in the diff against the PR base; CI prints them and fails
  if the PR body lacks a `## Suppressions` section naming each (when run on a PR). Keep it simple; document how.
- **Coverage ratchet, core only.** Branch coverage of `src/Resultful` (coverlet collector or
  Microsoft.Testing.Platform code coverage, whichever the test projects already support) measured in CI; the floor
  is committed (`eng/coverage-floor.json`) and CI fails if coverage drops below it.
- **Reference model.** A tiny, obviously-correct model of today's 0.2 `Result`/`Result<T>`/`Result<T,TError>`
  semantics in tests (lists and bools, no Resultful code), with the first property laws checked against the real
  library using the property-testing setup already in `tests/Resultful.Consumption` (PropertyLawTests): at least
  `Map` identity/composition, `Bind` associativity/left identity, and agreement of `Match` with the model.
- **`release-check` scripts**, file-based apps in `eng/`, run in CI against the packed beta06 baseline and against
  the current pack (they should report "no differences" today):
  - `eng/api-diff.cs`: public API of two `Resultful.dll`s (System.Reflection.Metadata), per target, diffed against
    a committed list (`eng/api-diff-0.2.0.txt`, empty now).
  - `eng/il-diff.cs`: methods whose IL body bytes differ, into `eng/il-diff-0.2.0.txt` (empty now).
  - `eng/verify-package.cs` extended (not replaced) to diff nuspec dependency groups and the file list against a
    baseline nupkg, version excluded.
  - The baseline `Resultful 0.2.0-beta06` is packed in CI from the `0.2.0-beta06` git tag (verify the tag exists;
    if not, use the commit nuget.org's beta06 points to and say so) and kept as an artifact. Each script has a
    self-test showing it reports a seeded difference.
- **Culture.** The consumption tests also run under `tr-TR` and invariant culture, set per test run (environment
  or runsettings), not per test.
- Every CI job passes on the PR. Nothing under `src/` changes.
